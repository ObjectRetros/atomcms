# Installing and deploying Atom CMS

## Requirements

Use PHP 8.5 or newer, Composer 2, a Node.js LTS version compatible with `package.json`, and MySQL or MariaDB compatible with your emulator. CI runs PHP 8.5 and MariaDB 11.8. Atom supports Arcturus Morningstar 3.5.5 and Ada; a hotel uses one emulator driver and database throughout its lifetime.

Install the PHP extensions required by Composer, including cURL, GD, sockets, intl, mbstring and PDO MySQL. Laravel also needs Ctype, DOM, Fileinfo, Filter, Hash, OpenSSL, PCRE, PDO, Session, Tokenizer and XML. Check the installed platform with `composer check-platform-reqs` after installing dependencies. See [Laravel's server requirements](https://laravel.com/docs/13.x/deployment#server-requirements).

## First installation

Keep the site accessible only to the operator until the browser installation is complete. Run commands from the repository root as the deployment user.

```bash
git clone https://github.com/ObjectRetros/atomcms.git
cd atomcms
composer setup
```

`composer setup` copies `.env.example` when needed, installs locked PHP and Node dependencies, and runs `atom:install`. The installer selects the emulator, configures the database, generates a missing application key, links storage, runs migrations and seeders, and builds the selected theme. Set `APP_URL` to the address you will use. The default `.env.example` database and mail hosts belong to local Docker services; replace them when running outside Compose.

For Ada, start Ada against its database first so Entity Framework creates the emulator schema, then select Ada in the installer. For an existing Arcturus hotel, skip the base import. Back up an existing hotel database before adding Atom. The installer refuses to replace a recognized emulator database, including when `--fresh` is passed.

To install dependencies separately on Linux:

```bash
cp .env.example .env
# Configure .env for your database and application URL.
composer install
npm ci
php artisan atom:install --emulator=arcturus
```

On Windows, run the same sequence with `copy .env.example .env` in Command Prompt, or `Copy-Item .env.example .env` in PowerShell. For Ada, use `--emulator=ada`; for an existing Arcturus schema, add `--skip-arcturus`. This sequence is for a new checkout: preserve an existing `.env` and `APP_KEY` when updating.

Useful installer options:

| Option | Purpose |
| --- | --- |
| `--emulator=ada` | Install Atom against Ada's existing EF-migrated database. |
| `--skip-arcturus` | Preserve an existing Arcturus schema and skip base/catalog imports. |
| `--sql=/path/to/database.sql` | Use your own Arcturus base dump (`.sql` or `.sql.gz`). |
| `--catalog-sql=/path/to/catalog.sql` | Import a custom catalog after the Arcturus base. |
| `--skip-catalog` | Keep the catalog in the base dump. |
| `--theme=atom` or `--theme=dusk` | Activate and build the selected bundled theme. |
| `--skip-build` | Build assets separately with `npm run build:atom` or `npm run build:dusk`. |
| `--fresh` | Destroy tables only in a disposable database; refused for a recognized hotel schema. |

For local development, run `php artisan serve --host=127.0.0.1` and visit `/installation`. For a web server, set its document root to `public/` and complete `/installation` through the restricted site before admitting visitors. Laravel's development server is for local development.

Compose provides separate `mariadb` and `mariadb-ada` services and volumes. Ada uses `mariadb-ada:3306` from Compose or `127.0.0.1:3308` from the host. Its local default database is `atomcms_ada`, with username `atomcms` and password `password`. Point Ada at that database first, then point Atom's `DB_*` variables at it and set `EMULATOR_DRIVER=ada`. Replace these sample credentials in deployments.

## Web server permissions

The web process needs read access to application files and write access to `storage/` and `bootstrap/cache/`. Keep application source, `.env`, dependency files and Git metadata owned by the deployment user. The web server must serve only `public/`. See [Laravel's deployment guidance](https://laravel.com/docs/13.x/deployment).

On Linux, substitute your actual web process group for `www-data`:

```bash
sudo chown -R "$USER":www-data storage bootstrap/cache
chmod -R u+rwX,g+rwX,o-rwx storage bootstrap/cache
```

On IIS, give the site's application pool identity read/execute access to the application and **Modify** access to `storage` and `bootstrap/cache`. Apply permissions to that site's identity, such as `IIS AppPool\AtomCMS`. Do not grant `IUSR` or `IIS_IUSRS` Full control over the repository. Creating the `public/storage` link may require Windows Developer Mode or an elevated deployment command; the web process does not need elevation.

Badge management can also write the configured Nitro/Flash external-texts files. If using that feature, grant write access to those specific files and required containing directories, without making the entire client or application writable.

## Production configuration

Set the real hostname and production values before caching configuration:

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://hotel.example
SESSION_SECURE_COOKIE=true
TRUSTED_PROXIES=
```

An empty `TRUSTED_PROXIES` suits a server receiving visitors directly. Behind a reverse proxy, set its exact IPs/CIDRs as a comma-separated list. Use `*` only when the origin accepts traffic exclusively from trusted proxies and those proxies replace visitor-supplied forwarded headers. Client IPs affect bans, throttling and registration limits.

Configure HTTPS at the web server or trusted proxy. `FORCE_HTTPS=true` forces generated Laravel URLs to use HTTPS when necessary; it does not configure TLS or restrict access to the origin. Keep `.env` and backups outside the public document root, and retain the existing `APP_KEY` across deployments so encrypted data remains readable.

Set real SMTP credentials and a valid sender for password reset mail. Configure [bot protection](4.-Bot-protection.md) before opening registration. If using Cloudflare, disable Rocket Loader for the site because it interferes with Atom's JavaScript.

## Updating an installed hotel

Back up the database, `.env` and uploaded assets, and validate the release against a separate copy of the hotel's database. Deploy reviewed code and its lockfiles as the deployment user. Preserve your emulator driver, environment file and application key.

For an in-place deployment, put Laravel into maintenance mode, deploy the reviewed code, then install its dependencies and migrate:

```bash
php artisan down
# Deploy the reviewed release code here, preserving .env and storage/.
composer install --no-dev --prefer-dist --optimize-autoloader
composer check-platform-reqs --no-dev
npm ci
npm run build:atom
npm run build:dusk
php artisan config:clear
php artisan migrate --force
php artisan storage:link
php artisan optimize
php artisan reload
php artisan up
```

Only run `up` after the preceding steps succeed. Restart PHP/opcache as required by your hosting platform. Long-running processes need a process monitor to restart them after `reload`. Build both themes when both must remain available; a deployment that ships only one theme can build that theme alone. Node dependencies are build-time dependencies and may be built in CI instead of on the web server.

Use `migrate` for updates. `migrate:fresh`, base SQL imports and `composer setup` are installation tools, not an upgrade sequence. Run additional seeders only when the release requires them: seeders can change existing content or configuration. Do not enable `RENAME_COLLIDING_TABLES` as a general upgrade setting; review each collision and back up the affected data before allowing a rename.

`optimize` caches Laravel configuration, events, routes and views. Rebuild configuration with `php artisan config:cache` after changing `.env`; application code should read `config()`, with `env()` confined to configuration files. See [configuration caching](https://laravel.com/docs/13.x/configuration#configuration-caching).

## Scheduler and queues

Atom schedules `paypal:reconcile` every five minutes in `app/Console/Kernel.php`. Run Laravel's scheduler every minute, including when the default queue connection remains `sync`:

```cron
* * * * * cd /path/to/atomcms && php artisan schedule:run >> /dev/null 2>&1
```

On Windows, use Task Scheduler to run `php artisan schedule:run` every minute with the repository as its working directory. Check `php artisan schedule:list` to confirm the reconciliation task is registered. See [Laravel scheduling](https://laravel.com/docs/13.x/scheduling#running-the-scheduler).

The default `QUEUE_CONNECTION=sync` executes jobs inline. If switching to an asynchronous queue, provision its storage and run supervised workers as described in [Laravel queues](https://laravel.com/docs/13.x/queues#running-the-queue-worker).

## Troubleshooting

For cURL error 60 on Windows, download the current [CA bundle from cURL](https://curl.se/docs/caextract.html), store it as `C:/certs/cacert.pem`, and configure the PHP installation used by the failing process:

```ini
curl.cainfo = "C:/certs/cacert.pem"
openssl.cafile = "C:/certs/cacert.pem"
```

Restart the affected PHP/web process. Keep certificate verification enabled. Read [error logging](Error-logging.md) for diagnosing failures with production debug mode disabled.
